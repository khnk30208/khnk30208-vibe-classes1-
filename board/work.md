# 로그인 기능이 있는 게시판 예제 - 요구사항

> 이 문서가 기능 명세다. 여기 없는 기능은 만들지 않는다.
> 바꾸고 싶은 항목은 이 파일을 직접 수정한 뒤 작업을 요청한다.


# 1. 개요

- 회원가입 / 로그인 후 글을 쓰고 읽을 수 있는 게시판
- 백엔드 서버 없이 localStorage 를 저장소로 쓰는 목(mock) API 로 동작한다
- `npm run dev` 하나로 전체가 동작해야 한다


# 2. 화면 구성

- **URL 라우팅을 쓰지 않는다.** 주소는 항상 그대로이고, `MainLayout` 의
  컨텐츠 영역만 상태에 따라 바뀐다 (페이지 이동·새로고침 없음)
- 화면 상태는 `MainLayout` 과 `BoardPage` 두 곳에서만 관리한다

## 2.1 MainLayout 상태

| 상태 | 값 | 설명 |
|---|---|---|
| `activeMenu` | `'board'` | 선택된 메뉴. 기본값 `'board'` |
| `authView` | `null` \| `'login'` \| `'signup'` | 인증 화면 표시 여부. 기본값 `null` |

- 컨텐츠 영역은 이 순서로 그린다
  1. `authView` 가 `null` 이 아니면 → 로그인 / 회원가입 화면
  2. 아니면 → `activeMenu` 에 해당하는 컨텐츠 (현재는 게시판)
- 로그인·회원가입은 **메뉴가 아니다.** Header 의 `로그인` / `회원가입` 버튼이
  `authView` 를 바꾼다
- 인증 화면을 닫을 때(로그인 성공 또는 취소) `authView` 만 `null` 로 되돌린다.
  `activeMenu` 는 건드리지 않으므로 보고 있던 화면으로 그대로 돌아온다

## 2.2 게시판(BoardPage) 상태

| 상태 | 값 | 설명 |
|---|---|---|
| `view` | `'list'` \| `'detail'` \| `'write'` \| `'edit'` | 게시판 내부 화면. 기본값 `'list'` |
| `selectedPostId` | 게시글 id \| `null` | 상세·수정에서 사용. 기본값 `null` |

| `view` | 화면 | 로그인 필요 |
|---|---|---|
| `list` | 게시글 목록 (기본 진입) | X |
| `detail` | 글 상세 | X |
| `write` | 글쓰기 | O |
| `edit` | 글 수정 | O (작성자 본인) |

## 2.3 화면 전환 규칙

- 앱 최초 진입 화면은 `게시판 > 목록` 이다
- 전환 함수는 `BoardPage` 가 만들어 하위 컴포넌트에 props 로 내려준다
  (`goList()`, `goDetail(id)`, `goWrite()`, `goEdit(id)`)
- 하위 컴포넌트가 `view` 상태를 직접 바꾸지 않는다
- 브라우저 뒤로가기는 화면 전환과 연결하지 않는다.
  되돌아갈 때는 화면 안의 `목록` / `취소` 버튼을 쓴다
- 새로고침하면 화면 상태는 초기값(`게시판 > 목록`)으로 돌아간다.
  로그인 상태만 localStorage 로 유지된다
- 로그인이 필요한 화면(`write`, `edit`)의 진입 버튼은 조건을 만족할 때만 노출한다.
  그래도 진입 시점에 로그인 상태를 한 번 더 확인하고,
  비로그인이면 화면을 바꾸지 않고 `authView = 'login'` 으로 전환한다


# 3. 기능 상세

## 3.1 회원가입
- 입력: 아이디, 비밀번호, 비밀번호 확인, 닉네임
- 검증: 아이디 4자 이상 / 비밀번호 6자 이상 / 비밀번호 확인 일치 / 아이디 중복 불가
- 성공하면 자동 로그인 후 인증 화면을 닫는다 (`authView = null`) → 게시판 목록이 보인다

## 3.2 로그인 / 로그아웃
- 입력: 아이디, 비밀번호
- 실패 시 "아이디 또는 비밀번호가 올바르지 않습니다." 표시 (어느 쪽이 틀렸는지 구분하지 않는다)
- 새로고침해도 로그인 상태가 유지된다
- 헤더에 로그인 시 `닉네임 + 로그아웃`, 비로그인 시 `로그인 + 회원가입` 표시
- 로그인 성공 시 인증 화면을 닫고, 인증 화면에 들어오기 직전 보던 화면으로 돌아간다
- 로그아웃해도 화면은 바뀌지 않는다. 보고 있던 화면에 그대로 머물고
  로그인이 필요한 버튼만 사라진다
- 로그인 / 회원가입 화면끼리는 서로 링크로 오갈 수 있다 (`authView` 값만 바꾼다)

## 3.3 게시글 목록
- 컬럼: 번호, 제목, 작성자, 작성일, 조회수
- 최신순 정렬, 한 페이지 10건, 하단 페이지네이션
- 제목 클릭 시 `goDetail(id)` 로 상세 화면으로 전환
- 제목/작성자 검색 (선택 구현)
- 글이 없으면 "등록된 게시글이 없습니다." 표시
- 로그인 상태일 때만 `글쓰기` 버튼 노출 (누르면 `goWrite()`)

## 3.4 글쓰기 / 수정
- 입력: 제목(필수, 100자 이내), 내용(필수)
- 저장 후 `goDetail(id)` 로 그 글 상세 화면으로 전환
- `취소` 를 누르면 글쓰기는 `goList()`, 수정은 `goDetail(id)` 로 되돌아간다
- 수정 화면은 기존 값이 채워진 상태로 열린다

## 3.5 글 상세
- 제목, 작성자, 작성일, 조회수, 내용 표시
- 진입 시 조회수 1 증가 (본인 글도 동일하게 증가)
- 작성자 본인일 때만 `수정` / `삭제` 버튼 노출 (수정은 `goEdit(id)`)
- 삭제는 확인창을 거친 뒤 `goList()` 로 목록 화면으로 전환
- `목록` 버튼으로 언제든 `goList()` 할 수 있다


# 4. 데이터 모델

```js
// users
{ id, username, passwordHash, nickname, createdAt }

// posts
{ id, title, content, authorId, authorNickname, viewCount, createdAt, updatedAt }
```

- localStorage 키: `board:users`, `board:posts`, `board:token`, `board:currentUser`
- 최초 실행 시 시드 데이터를 넣는다: 사용자 2명, 게시글 15건
  (페이지네이션이 바로 보이도록 10건 이상)


# 5. UI

- 전체 폭 960px, 중앙 정렬
- 밝은 배경 + 회색 테두리의 담백한 관리자 화면 톤
- 목록은 table, 폼은 label + input 세로 배치
- 버튼은 기본/주요(파랑)/위험(빨강) 3종
