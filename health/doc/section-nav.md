# 2. 결정 사항

## 2.1 섹션 구성 (사용자 확정)

기존 3개에 **운동 추천**과 **내기록**을 더해 6개로 만든다.

| # | 섹션 | 근거 | 상태 |
|---|---|---|---|
| 1 | 건강 | work.md H-1~H-5 | 이미 완료 |
| 2 | 필요한 영양소 | work.md 단계 5 / H-6 | 이번 작업 |
| 3 | 음식 추천 | work.md 단계 5 / H-6 | 이번 작업 |
| 4 | 운동 추천 | work.md H-7 | 이번 작업 |
| 5 | 주변 헬스장 | work.md 단계 6 | 이번 작업 |
| 6 | 내기록 | work.md 단계 7 | 이번 작업 |

## 2.2 헬스장 — 키 없이도 동작한다 (사용자 확정)

- 위치: 브라우저 Geolocation → 거부/실패 시 안내 문구. 위치를 저장하지 않는다
- 검색: **OpenStreetMap Overpass API** (키 불필요·무료·CORS 허용) 로
  `leisure=fitness_centre` / `sport=fitness` 를 반경 검색한다
- `.env` 에 `VITE_KAKAO_MAP_KEY` 가 채워져 있으면 **카카오 로컬 검색으로 자동 전환**한다
  (한국 데이터가 훨씬 정확하다). 키가 없으면 Overpass 결과를 쓴다
- 거리 계산은 `utils/geo.js` 의 Haversine 으로 직접 한다
- **OSM 은 한국 헬스장 데이터가 성깁니다.** 결과가 적을 수 있다는 안내를 화면에 둔다

## 2.3 영양소·운동 추천의 근거 (중요)

- 특정 질병을 단정하지 않는다 (`CLAUDE.md` 5장). **일반 영양 지침 수준**으로만 쓴다
- 판정 → 영양소 매핑은 `service/nutritionService.js` 한 곳에 모으고,
  음식·영양소 사전 데이터는 `assets/nutrients.json` 으로 분리한다
- 운동 소모 열량은 **MET 공식**으로 계산한다
  `kcal = MET × 3.5 × 체중(kg) ÷ 200 × 분`
- 추천 문구는 "~에 도움이 됩니다" 수준까지만. "치료", "개선됩니다" 를 쓰지 않는다

## 2.4 내기록

- 분석 결과를 사용자가 **[기록 저장]** 을 눌렀을 때만 localStorage 에 쌓는다
- 저장 항목: 날짜, 체중, BMI, 체지방률, TDEE
- 체중·BMI 추이를 **인라인 SVG 라인 차트**로 그린다.
  차트 라이브러리를 새로 설치하지 않는다 (참고 HTML 도 인라인 SVG 를 썼다)
- 기록 개별 삭제 / 전체 삭제를 제공한다
- "이 브라우저에만 저장됩니다" 를 안내한다

## 2.5 우측 아이콘 독 (사용자 확정: 아이콘 + 라벨 세로 레일)

- 화면 **우측에 고정**(`position: fixed`), 세로 중앙 정렬
- 항목마다 **아이콘 + 짧은 한글 라벨**. 무슨 메뉴인지 바로 보이게 한다
- 클릭하면 해당 섹션으로 **부드럽게 스크롤**한다
  (`prefers-reduced-motion` 이면 즉시 이동)
- 스크롤에 따라 **현재 보고 있는 섹션이 자동으로 활성 표시**된다 (스크롤 스파이)
- 헤더가 sticky 56px 이므로 스크롤 목적지에서 그만큼 빼 준다
  → 각 섹션에 `scroll-margin-top` 을 준다
- 반응형
  - 1200px 미만: 라벨을 감추고 아이콘만 남긴다
  - 720px 미만: 독을 감춘다. 좁은 화면에서 콘텐츠를 가리는 편이 더 나쁘다
- 접근성: `<nav aria-label="섹션 바로가기">`, 활성 항목에 `aria-current="true"`,
  아이콘만 남는 상태에서도 `title` 과 `aria-label` 로 이름을 전달한다
- **대시보드(홈) 화면에서만 보인다.** 게시판·입력 폼에서는 렌더하지 않는다


# 3. 파일 계획

```
src/
  assets/
    nutrients.json        영양소 사전 + 영양소별 음식
    exercises.json        운동 목록 (MET, 부위, 강도)
  api/
    gymApi.js             Overpass / 카카오 로컬 호출만
    recordApi.js          localStorage 읽기·쓰기만
  service/
    nutritionService.js   분석 결과 → 부족 영양소 → 음식
    exerciseService.js    분석 결과 → 운동 추천 + MET 소모 계산
    gymService.js         위치 + 검색 결과 → 거리순 정렬
    recordService.js      기록 저장·삭제·추이 계산
  utils/
    geo.js                Haversine 거리 (순수 함수)
  components/
    SectionDock.jsx       우측 아이콘 독 + 스크롤 스파이
    SectionDock.module.css
    GymCard.jsx           위치 요청 · 결과 목록 (비동기 상태 보유)
    GymCard.module.css
    RecordCard.jsx        기록 목록 + SVG 추이 차트
    RecordCard.module.css
  pages/
    HomePage.jsx          섹션 6개 배치 + 독 연결
```

- 레이어 규칙 그대로: `pages` → `service` → `api`. `service` 는 React 를 import 하지 않는다
- 독의 항목 정의는 `constants/sections.js` 한 곳에서만 관리한다 (메뉴와 같은 원칙)


# 4. 완료 조건

- 대시보드에 섹션 6개가 보이고, 분석 전/후 상태가 각각 자연스럽다
- 분석하면 영양소·음식·운동 카드가 실제 내용으로 채워진다
- 우측 독의 항목을 누르면 해당 섹션으로 스크롤되고, 헤더에 가려지지 않는다
- 스크롤하면 현재 섹션이 독에서 자동으로 활성화된다
- 1200px 미만에서 라벨이 사라지고, 720px 미만에서 독이 사라진다
- 위치 권한을 거부해도 화면이 깨지지 않고 안내가 나온다
- 기록을 저장하면 추이 차트가 그려지고, 삭제하면 사라진다
- 라이트/다크 모두 정상, 콘솔 에러 0건, `npm run lint` 통과
