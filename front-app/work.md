# 로그인 기능이 있는 게시판 예제 - 요구사항

> 이 문서가 기능 명세다. 여기 없는 기능은 만들지 않는다.
> 바꾸고 싶은 항목은 이 파일을 직접 수정한 뒤 작업을 요청한다.


# 1. 개요

- 회원가입 / 로그인 후 글을 쓰고 읽을 수 있는 게시판
- 백엔드 서버 없이 localStorage 를 저장소로 쓰는 목(mock) API 로 동작한다
- `npm run dev` 하나로 전체가 동작해야 한다


# 2. 화면 및 라우트

| 경로 | 화면 | 로그인 필요 |
|---|---|---|
| `/login` | 로그인 | X |
| `/signup` | 회원가입 | X |
| `/posts` | 게시글 목록 (기본 진입) | X |
| `/posts/new` | 글쓰기 | O |
| `/posts/:id` | 글 상세 | X |
| `/posts/:id/edit` | 글 수정 | O (작성자 본인) |

- `/` 로 들어오면 `/posts` 로 리다이렉트
- 로그인 필요한 경로에 비로그인 상태로 접근하면 `/login` 으로 보내고,
  로그인 성공 후 원래 가려던 경로로 되돌린다


# 3. 기능 상세

## 3.1 회원가입
- 입력: 아이디, 비밀번호, 비밀번호 확인, 닉네임
- 검증: 아이디 4자 이상 / 비밀번호 6자 이상 / 비밀번호 확인 일치 / 아이디 중복 불가
- 성공하면 자동 로그인 후 `/posts` 로 이동

## 3.2 로그인 / 로그아웃
- 입력: 아이디, 비밀번호
- 실패 시 "아이디 또는 비밀번호가 올바르지 않습니다." 표시
  (어느 쪽이 틀렸는지 구분해서 알려주지 않는다)
- 새로고침해도 로그인 상태가 유지된다
- 헤더에 로그인 시 `닉네임 + 로그아웃`, 비로그인 시 `로그인 + 회원가입` 표시

## 3.3 게시글 목록
- 컬럼: 번호, 제목, 작성자, 작성일, 조회수
- 최신순 정렬, 한 페이지 10건, 하단 페이지네이션
- 제목 클릭 시 상세로 이동
- 제목/작성자 검색 (선택 구현)
- 글이 없으면 "등록된 게시글이 없습니다." 표시
- 로그인 상태일 때만 `글쓰기` 버튼 노출

## 3.4 글쓰기 / 수정
- 입력: 제목(필수, 100자 이내), 내용(필수)
- 저장 후 해당 글 상세로 이동
- 수정 화면은 기존 값이 채워진 상태로 열린다

## 3.5 글 상세
- 제목, 작성자, 작성일, 조회수, 내용 표시
- 진입 시 조회수 1 증가 (본인 글도 동일하게 증가)
- 작성자 본인일 때만 `수정` / `삭제` 버튼 노출
- 삭제는 확인창을 거친 뒤 목록으로 이동


# 4. 데이터 모델

```js
// users
{ id, username, passwordHash, nickname, createdAt }

// posts
{ id, title, content, authorId, authorNickname, viewCount, createdAt, updatedAt }
```

- localStorage 키: `board:users`, `board:posts`, `board:token`, `board:currentUser`
- 최초 실행 시 시드 데이터를 넣는다: 사용자 2명, 게시글 15건
  (페이지네이션이 바로 보이도록 10건 이상)
- 시드 계정은 화면 어딘가(로그인 페이지 하단 등)에 안내한다


# 5. UI

- 전체 폭 960px, 중앙 정렬
- 밝은 배경 + 회색 테두리의 담백한 관리자 화면 톤
- 목록은 table, 폼은 label + input 세로 배치
- 버튼은 기본 / 주요(파랑) / 위험(빨강) 3종
